VWFA-only vs. VWFA + Wernicke-ERP (union), per subject

Two fully independent detectors: VWFA uses envelope-threshold crossing (vwfa_word_detection/word_detection.py, untouched); Wernicke-ERP uses genuine ERP analysis — band-passed signal, sign preserved, scored across all 4 ERP_COMPONENTS windows (P1/N170/N250/N400) per candidate, latency-corrected back to an estimated word onset (vwfa_wernicke_word_detection/wernicke_erp_detection.py). They're combined by union, not confirmation: a Wernicke-ERP marker is added only if it doesn't already overlap a VWFA marker, so it can only ever catch words VWFA missed, never duplicate or override one VWFA already found (combine.py).

Headline finding: the union added very little — only extra correct words out of true words overall ( recall gain). Why: VWFA alone already places a ±200ms marker around ~640 candidates per ~285s block — roughly 90% of the block's total timeline is already covered by some VWFA marker, leaving very little uncovered time for a second detector to add anything under a purely temporal-exclusion union rule.

Design note: the Wernicke-ERP detector only keeps the top decile of candidates by combined ERP-component strength (config.LOCAL_CALIB_HIGH_PCT) and a fixed 400ms N400-latency correction — both are single, un-tuned choices; a looser accept threshold or per-candidate latency (rather than one fixed value) might change this balance, untested here.
